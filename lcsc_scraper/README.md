# 商城商品数据采集系统（立创 / 华秋 / 云汉）

带网页可视化操作界面的电子元器件商城数据采集工具，支持并发采集与 Excel 导出。

## 支持站点

| 站点 | 采集范围 | 排序 | 类目模式 | 品牌模式 |
|---|---|---|---|---|
| 立创商城 (szlcsc.com) | 连接器 / 端子 / 按键开关（89 个子类） | 销量 | ✅ | ✅ |
| 华秋商城 (hqchip.com) | 连接器 / 开关及按键 / 线缆及配套（47 个子类） | 销量 | ✅ | ❌ |
| 云汉芯城 (ickey.cn) | 开关/继电器 + 连接器（48 个子类） | 综合（站点无销量排序） | ✅ | ❌ |

> 云汉芯城连接器为两级类目：界面展示 25 个二级类目，采集时自动展开其三级子类并合并到该二级类目名下。

## 功能

- **按类目采集**：勾选子类目（默认全选三大类），每个子类目按**销量**排序采集前 N 个商品
- **按品牌采集**（仅立创）：与类目采集共用分组逻辑，对每个选中品牌在三大类的全部子类目下按「类目 + 品牌」过滤，每个品牌每个子类目按**销量**采集前 N 个商品；同子类目跨品牌合并到同一 sheet，按商品去重
  - 开始前先用每个品牌的品牌页分面（`catalogGroup`，与「类目 + 品牌」列表接口 `totalCount` 一致）**探测各子类目的在售商品数**，只为有商品的「品牌 × 子类目」组合建分组、发请求；进度目标 = Σ min(N, 该品牌在该子类的商品数)，即真实待采条数（例如 2 个品牌 × 89 个子类目，若只有 9 个组合有商品，目标就是这 9 个组合的条数，而不是 89 × 2 × N）
    - 品牌页现被**腾讯验证码**拦截时会自动降级：改用「类目 + 品牌」列表接口**逐子类目精确统计**，结果与站点「共 N 件相关商品」一致（日志会显示「品牌页探测失败，改用「类目+品牌」逐类目统计」）
  - 站点商品不足 N 条（或品牌页探测失败降级为全类目尝试）时，目标会自动下调到实际可得条数，保证进度条能跑满
- **商品数据**：编号、型号、品牌、类目、描述、封装、库存、销量、起订量、单价/价格梯度、图片、详情链接等
- **完整参数表**：每个商品抓取详情页参数，**合并成 Excel 的单个 `参数` 列**，格式 `名称:值；名称:值；…`
  （值本身含分号的会被替换为 `,`，避免与列内的 `；` 分隔符混淆；空值与 `-` 不写入）
- **引脚图 / 焊盘图**：**已不再抓取**（导出不需要这两列，每个商品可省一次 `lceda.cn` 请求）。
  `LcscClient.pinpad_urls()` 保留，需要时在 `LcscSite.enrich()` 里接回即可
- **采集去重**：全任务共享一个去重集合，同一商品在多个子类目 / 品牌下只采集一次（含品牌模式跨品牌同子类目去重）
- **数据库去重**：连接服务器数据库 `nshop_tp8_v2.sp_goods`，**已有商品编号或型号的商品直接跳过不采集**（默认开启；含 `Product_Source = 1` 的商品）
  - 子类目状态分三种：`2/2 ✅` + `跳过N`（正常采集，另有 N 条已存在/图片不合规被跳过）、`全部已跳过（N）`（该类目商品全部被跳过）、`无在售商品`（该类目站点确实没有商品）
- **图片过滤**：跳过「图片不是商品实拍图」的商品（立创品牌证书图、云汉默认占位图），默认开启；可切换为「只保留有商品实拍图」（连无图商品一起跳过）
- **数据手册过滤**：跳过没有数据手册 PDF 链接的商品，默认开启，**仅对提供该字段的站点生效**（立创；华秋 / 云汉 实测 0%，勾选也不会让它们被清空）
- **商品预览筛选**：商品数据卡片支持「只看有图」勾选（仅统计有商品实拍图的商品，计数同步收窄），点击类目胶囊可筛选查看单个类目（再点一次取消）
- **商品数据预览**：网页「运行日志与结果导出」下方新增商品数据卡片，**只展示通过「采集去重 + 数据库去重 + 图片过滤 + 数据手册过滤」后的商品**，并按类目分组、汇总各类目条数（顶部显示「去重后共 N 条 · M 个类目 · 跳过库中已有 K 条 · 跳过图片不合规 J 条 · 跳过无数据手册 D 条」及类目条数标签）。每条含图片 / 型号 / 编号 / 品牌 / 封装 / 库存 / 单价。
- **可视化界面**：站点切换、类目/品牌勾选、并发配置、实时进度、运行日志、下载 Excel
- **并发**：异步 HTTP（httpx），可配置单请求并发数与同时进行的子类/品牌数
- **任务持久化**：数据实时落盘，重启后仍可导出已完成部分

## 图片过滤（默认开启）

部分商品的「图片链接」并不是商品实拍图，而是站点给的资质图 / 占位图：

| 站点 | 特征 | 实测占比 |
| --- | --- | --- |
| 立创 | URL 含 `/upload/public/brand/product/certificate/`（**品牌证书图**：同一品牌下所有商品共用一张，缩略图完全相同） | 860 / 8543 |
| 云汉 | URL 含 `default_list_logo`（默认占位图） | 89 / 8543 |

这些图导入商城后等同「无图」，因此默认跳过。网页「图片过滤」下拉三档：

- **跳过非商品图（证书图 / 占位图）**（默认）：只排掉上表两类，无图商品照常采集。实测跳过约 11.6%。
- **只保留有商品实拍图**：连**无图**商品一起跳过。注意无图占比很高（实测约 44%），选此项后目标条数会明显下调，
  且华秋等站点若列表/详情都没给图，商品会被大幅过滤。
- **不过滤**：回到旧行为。

判定逻辑见 `lcsc_scraper/scraper.py` 的 `is_non_product_image()` / `has_product_image()` / `passes_image_filter()`，
URL 特征集中在 `NON_PRODUCT_IMAGE_MARKS`，需要增删特征改这一处即可。预览区的「只看有图」也按同一标准（证书图 / 占位图不算有图）。

## 数据库去重（可选）

采集开始前会读取 `nshop_tp8_v2.sp_goods` 中已有商品的 **`rsku_hidden`**（商品编号）与 **`sku`**（型号）字段，
采集到的**「商品编号」命中 `rsku_hidden`**、或**「型号」命中 `sku`** 即跳过，避免重复入库。

> `rsku_hidden` 实际存储为竖线包裹形式 `|C367017|`，代码读取时按 `|` 拆分取裸值后再比对（精确比较）。
> `sku` 存的是型号 / 规格（如 `0-1217891-1`），比对前做归一化：全角转半角（NFKC）、去掉所有空白、统一小写，
> 因此站点与库中书写差异（多余空格、大小写）也能命中。
> 连接必须使用 `utf8mb4`（代码已固定），否则中文乱码。

对比字段（商品编号字段）默认 `rsku_hidden`，可通过 `codeColumn` 修改；留空则自动探测。
**型号对比字段**默认 `sku`，可通过 `skuColumn` 修改；留空 `""` 表示关闭「按型号去重」这条规则。
核对 `sp_goods` 实际字段名：

```bat
py -3.12 -m lcsc_scraper.db
```

该命令会打印 `sp_goods` 的全部字段名，并给出识别到的商品编号 / 型号对比字段，以及两者各自的已有条数。

连接参数优先级（后者覆盖前者）：

1. 内置默认值
2. `lcsc_scraper/db_config.json`（推荐，含密码，勿提交版本库）
3. 环境变量 `DB_HOST` / `DB_PORT` / `DB_USER` / `DB_PASSWORD` / `DB_NAME` / `DB_TABLE` / `DB_CODE_COLUMN` / `DB_SKU_COLUMN`
4. 网页「数据库去重设置」中填写的值（仅非空字段生效）

示例 `db_config.json`：

```json
{
  "enabled": true,
  "host": "服务器IP",
  "port": 3306,
  "user": "root",
  "password": "你的密码",
  "database": "nshop_tp8_v2",
  "table": "sp_goods",
  "codeColumn": "rsku_hidden",
  "skuColumn": "sku",
  "excludeProductSource": null
}
```

- `codeColumn`：商品编号对比字段名（与采集到的「商品编号」对比），默认 `rsku_hidden`；留空 `""` 表示按候选名自动探测。
- `skuColumn`：型号对比字段名（与采集到的「型号」对比），默认 `sku`；留空 `""` 表示**关闭**「按型号去重」这条规则。
- `excludeProductSource`：默认 `null` = **不排除**，即 `Product_Source = 1` 的商品**参与**去重判断（只被读取、绝不被采集写入或修改）。

  > 早期版本默认 `1`（PS=1 不参与去重），后经用户确认改为不排除：PS=1 共 4700 条里有 **4694 条没填
  > `rsku_hidden`**（编号规则匹配不到），只填了 `sku`；若整体排除，这些已经上架的商品会被重复采回
  > （实测某批 11 行里有 7 行属此类）。改后索引为 274153 个编号键 + 278981 个型号键。
  > 填具体值（如 `1`）可恢复「排除该 Product_Source」的行为，但改动前须经用户同意。

对应 SQL：`SELECT rsku_hidden, sku FROM sp_goods`（仅在配置了具体的 `excludeProductSource` 时才追加
`WHERE (Product_Source IS NULL OR Product_Source <> 该值)`）。

数据库不可用（未装 `pymysql` / 连不上 / 表不存在 / 找不到字段）时不会阻断采集，只是本次不按「已有商品」过滤，界面会显示「跳过(已有)」计数。

## 快速开始

```bat
cd D:\project\shopdatas_scrapy
pip install -r lcsc_scraper\requirements.txt
lcsc_scraper\start.bat
```

浏览器打开 <http://127.0.0.1:8123>。

> 仅立创商城有阿里云 WAF `acw_sc__v2` JS 挑战，求解依赖 **Node.js**（需在 PATH 中）；华秋、云汉无挑战。cookie 约 1 小时有效，过期自动重解。

## 使用建议

- **先测试**：每个子类/品牌条数填 `2` 快速验证全流程（两站点各约 1 分钟）
- **正式采集**：条数填 1500（立创站点单类上限 1500；华秋、云汉无此限制）
- 并发推荐 4~8，避免触发限流
- 结果文件在 `lcsc_scraper/data/` 目录

## 采集字段

编号 / 型号 / 品牌 / 品牌网址 / 品牌简介 / 类目 / 描述 / 封装 / 库存 / 近期销量 / 最小起订 / 包装方式 / 包装规格 / 单价 / 价格梯度 / 毛重 / 图片链接 / 数据手册PDF链接 / 关联型号 / 详情链接 / 简介备注 / **参数（单列，`名称:值；名称:值`）**

> Excel 共 22 列：不含 `引脚图链接` / `焊盘链接`（已不再抓取），参数由「每参数一列」改为合并的 `参数` 单列。

- 立创：价格梯度与毛重来自详情页；近期销量、包装方式来自列表
- **品牌网址 / 品牌简介**（仅立创）：来自品牌商品列表接口 `GET /brand/product` 的
  `result.searchResult.currentBrand`（`companyWebsite` / `companyContext`），按品牌缓存、每个品牌 1 次请求。
  品牌页 `list.szlcsc.com/brand/{id}.html` 已被腾讯验证码拦截，取不到这两个字段（早期版本因此这两列全空）。
- 华秋 / 云汉：单价来自列表（价格阶梯无公开接口，暂不采集）；近期销量站点不展示

## 技术要点

| 项目 | 立创商城 | 华秋商城 | 云汉芯城 |
|---|---|---|---|
| 类目 | 站点类目树 JSON | `/app/cn` 页面内嵌菜单 | 首页菜单 + `get-filter-result` 展开三级 |
| 商品列表 | `POST /category/product`（销量，pageSize≤30，单类上限 1500） | `GET /category/detailInfo.html?orderType=3&sort=2`（销量） | `GET search.ickey.cn/cate-search/get-search-result`（综合排序，pageSize≤50） |
| 品牌 | `/brand/page/catalog`；商品按「类目 + 品牌」用 `POST /category/product` 采 | 不支持 | 不支持 |
| 详情 | `item.szlcsc.com/{id}.html` 的 `__NEXT_DATA__` | `item.hqchip.com/{id}.html` 内联 `__NUXT__` | `www.ickey.cn/detail/{sku}/{sno}.html` 属性表格 |
| 反爬 | 阿里云 WAF `acw_sc__v2`（Node 执行挑战脚本求解） | 无 | 无 |
| 技术栈 | Python 3.10+ / FastAPI / httpx / openpyxl / Node.js | 同左 | 同左 |
